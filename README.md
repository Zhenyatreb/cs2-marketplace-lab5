# CS2 Market — лабораторна робота № 5

Навчальний full-stack вебзастосунок: HTML/CSS/JavaScript + Node.js/Express + PostgreSQL.

## Структура

- `public/` — клієнтська частина (8 HTML-сторінок, CSS, JavaScript та зображення).
- `server.js` — Express-сервер і REST API.
- `database.js` — підключення до PostgreSQL та початкові товари.
- `schema.sql` — структура таблиці `skins`.
- `.env.example` — приклад змінних середовища. Реальні секрети зберігаються у `.env`, який не завантажується в Git.
- `AI_LOG.md` — журнал використаних промптів і перевірок ШІ.

## Що реалізовано

- перегляд каталогу з бази даних;
- перегляд одного товару за ID;
- додавання, редагування та видалення скінів через REST API;
- перевірка даних на сервері;
- захист операцій керування кодом адміністратора;
- параметризовані SQL-запити;
- базові HTTP-заголовки Helmet та обмеження частоти API-запитів.

## Запуск локально

1. Встановити Node.js LTS.
2. Створити безкоштовний проєкт PostgreSQL у Neon та скопіювати pooled connection string.
3. У корені проєкту зробити копію `.env.example` з назвою `.env`.
4. У `.env` вставити `DATABASE_URL` з Neon та придумати власний `ADMIN_KEY`.
5. Відкрити термінал у VS Code в корені проєкту та виконати:

   ```bash
   npm install
   npm start
   ```

6. Відкрити `http://localhost:3000`.

Таблиця створюється автоматично під час першого запуску. Якщо вона порожня, сервер додає шість початкових скінів.

## REST API

| Метод | Маршрут | Призначення |
|---|---|---|
| GET | `/api/health` | Перевірка сервера та БД |
| GET | `/api/skins` | Отримати всі скіни |
| GET | `/api/skins/:id` | Отримати один скін |
| POST | `/api/skins` | Додати скін (потрібен `x-admin-key`) |
| PUT | `/api/skins/:id` | Оновити скін (потрібен `x-admin-key`) |
| DELETE | `/api/skins/:id` | Видалити скін (потрібен `x-admin-key`) |
| GET | `/api/admin/check` | Перевірити код адміністратора |

## Керування каталогом

1. Відкрити сторінку «Кабінет».
2. Ввести значення `ADMIN_KEY`, задане у `.env` або в налаштуваннях хостингу.
3. Після успішної перевірки з'явиться форма додавання товару.
4. Для редагування ціни або видалення товару перейти до каталогу — кнопки керування з'являться у картках.

Це навчальний захист адміністративних дій, а не повноцінна система облікових записів. Не використовувати справжні паролі Steam або банківські дані.

## Розгортання

Застосунок можна розгорнути як Node Web Service на Render. У Render потрібно під'єднати GitHub-репозиторій, використати Build Command `npm install`, Start Command `npm start`, а у Environment додати `DATABASE_URL` і `ADMIN_KEY`.

Neon використовується як окрема PostgreSQL-база, тому дані не залежать від тимчасової файлової системи сервера Render. На безкоштовному Render сервіс може засинати після періоду без запитів, тому перше відкриття після паузи може бути повільнішим.

Не завантажуйте `.env` або рядок підключення до бази даних у GitHub. У репозиторій можна додати лише `.env.example`.
